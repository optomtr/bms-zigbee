# Третий пакет: диагностика перед радиоэкспериментами

По согласованию с владельцем, свежих журналов после первых двух пакетов пока нет. Реализован пассивный сбор и анализ для программиста. Аппаратная причина не установлена; прошивка, CCA, мощность, APS RETRY и настройки сети не менялись.

- `harness/zamer/radio_capture.py`: отдельный MQTT-наблюдатель с пятью точными подписками, без publish и подключения к координатору. Контекст сборки/канала и результаты setPower, отдельные NCP/ASH-счётчики, счёт событий API/device report, разрывы, ограниченный JSONL с UTC и sequence. Секреты и DP-payload не сохраняются.
- `harness/zamer/radio.py`: офлайн-анализ JSONL, обычного и JSON-журнала Z2M. Проверенный контракт herdsman 10.10.0/bms.3, именованные счётчики, read-and-clear без ошибочного вычитания, контроль качества/насыщения/повторов, направления проверки вместо автоматического диагноза.
- [harness/RADIO.md](harness/RADIO.md): точные команды, ограничения часовых выборок, протокол повторяемых A/B/A и критерии до опыта.
- [Шаблон опыта](harness/examples/radio-experiment.json): намеренно незаполненные гипотеза и пороги; данных для go/no-go ещё нет.

Это диагностическая подготовка пунктов 60, 63, 68–70, 75, 80, 88, 91–94, 96–100 аудита. Она не означает, что перечисленные аппаратные эксперименты выполнены. Исправления MTORR 65–67 не включены без отдельного воспроизведения. Для воспроизведения фиксированного потока нагрузки следует использовать один сохранённый сценарий; текущий последовательный load замерщика не выдаётся за независимый генератор потока.

Проверка: из `harness` выполнить `python -m pytest -q`. Порядок всех 42 NCP и 27 ASH полей тест сверяет с реально упакованным `vendor/zigbee-herdsman.tgz`. Локально 74 теста проходят. Реальные MQTT/SLZB/HA не использовались. Номер образа остаётся 2.14.2-bms.8: пакет добавляет инструменты вне образа и не меняет его содержимое.

PR построен поверх второго пакета (#2), который зависит от первого (#1). Полный редизайн веб-интерфейса выполняется отдельной четвёртой фазой.
