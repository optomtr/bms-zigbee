# Четвёртая фаза: дружелюбный веб-интерфейс BMS Zigbee

Дополнение **2.14.2-bms.9**. Отдельный PR поверх третьего пакета; диагностические и радиоизменения не смешиваются с интерфейсом.

## Что изменилось

Вместо технической стартовой страницы открывается русскоязычный BMS-интерфейс с обзором дома, карточками устройств, комнатами, группами и диагностикой. Светлая тема, постоянная навигация на компьютере и нижнее меню на телефоне, поиск, фильтры, понятные состояния подключения и пустых списков. Данные берутся из существующего WebSocket Z2M: отдельного брокера, сервера и дублирующей базы нет.

- Устройства: последнее известное состояние, LQI с пояснением, датчики, поддержанные бинарные/числовые/enum-параметры из exposes, переименование. Каналы многоканального реле сохраняют свои property. Составные параметры не раскладываются в ошибочные независимые команды.
- Комнаты: отображение управляемых HA групп «Комната · …» в диапазоне 1000–1999. Их состав меняется в Home Assistant, чтобы UI не спорил с синхронизацией.
- Ручные группы: создание, переименование, добавление/удаление конкретного endpoint, удаление с подтверждением и без force, общие On/Off только при известном genOnOff у всех участников.
- Добавление устройства: понятные шаги и открытие permit_join на 60 секунд, возможность закрыть уже открытое подключение.
- Диагностика: подключение интерфейса, версия Z2M, статус start расширений, канал, отдельные наблюдаемые API/device-report события, последняя NCP-выборка при известном контракте, предупреждения и выгрузка сводки без полного конфига/секретов.
- Сложные функции исходного интерфейса сохранены в «Расширенных настройках» (`?advanced=1`), включая составные цветовые параметры, OTA, карту сети, bindings, настройки моделей и радио. Новый UI не объявляет, что заменил каждый редактор upstream.

## Поведение при ошибках

После нажатия показано «команда отправлена», не «устройство исполнило». Значения карточек обновляются по данным Z2M; они могут быть сохранёнными/оптимистичными. API-операции настройки используют transaction и ждут соответствующий response, ошибки остаются в диалоге, после 15 секунд без ответа предлагается проверить результат до повтора. Нет автоматической повторной отправки при переподключении. При потере связи команды блокируются, неизвестное состояние не подменяется OFF.

Ползунок отправляет значение на change, не каждое движение input. Токен frontend авторизации остаётся в памяти вкладки, не пишется в localStorage/sessionStorage. WebSocket и проверка токена — штатные, route/auth ядра не обходятся. Данные из MQTT вставляются как текст, не HTML. Уважены reduced motion, клавиатура, Escape и focus возврат из диалога.

`?demo=1` включает явно помеченные демонстрационные устройства. Этот режим не открывает WebSocket и не посылает команды; настройки групп в нём не симулируют успешную запись на сервер.

## Встраивание и проверка

`addon/bms_zigbee/rootfs/opt/bms-ui/` — исходные HTML/CSS/ES modules без сборщика и внешних CDN. Патч `0008-friendly-frontend.patch` добавляет раздачу через существующий Frontend и сохраняет upstream UI, API, base_url и авторизацию. Entrypoint включает `BMS_FRONTEND_PATH=/opt/bms-ui`. При отсутствии переменной остаётся upstream-интерфейс. UI-файлы входят в паспорт и проверяются при сборке/запуске образа.

Проверено локально:

- 916/916 тестов чистого Z2M, в том числе новые маршруты BMS/advanced под `/` и ingress-префиксом; 60/60 Tuya.
- 14/14 тестов сборки/согласованности/модели UI.
- Браузер Chromium: реальные исходники UI с изолированным WebSocket; включение, ползунок без потока input-команд, поиск, создание группы, error response, групповой OnOff, добавление endpoint, подтверждение удаления, permit_join, токен 4401, отсутствие storage токена, блокировка offline, текст вместо HTML-инъекции, отсутствие WebSocket в demo, все пять экранов при 390px и reduced motion.
- Визуально проверены desktop и mobile; живая HA/SLZB-сеть не использовалась. Настоящее переключение устройств и Supervisor ingress требуют отдельной приёмки на стенде.

Браузерный прогон:

```bash
npm install --prefix addon/.work/browser-check --no-audit --no-fund playwright@1.62.1
addon/.work/browser-check/node_modules/.bin/playwright install chromium
NODE_PATH="$PWD/addon/.work/browser-check/node_modules" node addon/test/frontend-browser.cjs
```

Локально браузер видимый; в CI без экрана — headless. GitHub Actions выполняет этот прогон, полный pipeline ядра/Z2M/Tuya/harness, проверку воспроизводимости stage и amd64 Docker build. Для повторной сборки после изменения патча: `bash addon/tools/check-z2m.sh`, затем `bash addon/stage.sh`.
