## 2.14.2-bms.7
- Общая очередь групповых и индивидуальных команд сохраняет порядок для пересекающихся устройств. Toggle и сцены тоже ждут бюджет; учитываются отдельные попытки вызова ZCL API.
- Состав групп проверяется на устройстве; изменения членства сериализованы с очисткой старых групп. Ожидающая команда отменяется с ошибкой, если состав группы изменился.
- У запросов Home Assistant есть предел ожидания; оборванное соединение и подписки восстанавливаются.
- Определение обработчиков Tuya больше не выполняет конвертеры «на пробу». Неудачный default response допускает повтор; состояние мощности меняется после успешного ответа NCP.
- Необязательная диагностика `advanced.bms_device_reports: true` отделяет входящие отчёты устройств от оптимистичных состояний MQTT.
- Ядро `10.10.0-bms.3` обязательно. Образ проверяет состав и контрольные суммы при сборке и старте, печатает версии в журнал.
- Эти изменения проверены без оборудования; эффект на SLZB-06M и домашней сети требует отдельного пилота. Параметры радио и CCA не изменены этим выпуском.

## 2.14.2-bms.6
- Склейка по каналам: команды каналам многоканальных реле (`state_l1`, `state_l2`) и одноканальным склеиваются в групповую по группе из этих каналов (например «Комната · <область>»). Одинаковые команды одному каналу в одном окне — одна. Оставшиеся команды разным каналам одного устройства идут по очереди, а не одновременно (модули Tuya с MCU теряли одновременные).

## 2.14.2-bms.5
- Ограничитель групповых команд: одной группе не чаще раза в секунду, всей сети не больше 8 групповых за 9 с; при быстрых командах (ползунок) уходит последнее значение, вкл/выкл не теряется. Групповая команда — широковещание, которое пересылает каждый повторитель; без ограничения серия забивала эфир и задерживала реле. Отключается `advanced.bms_group_throttle: false`.

## 2.14.2-bms.4
- Склейка команд: если Home Assistant почти одновременно шлёт многим лампам одинаковую команду (комната, своя группа HA, сцена), Z2M отправляет её группам Zigbee одной командой, остальным — по отдельности. Настройка `advanced.bms_group_coalescing` (по умолчанию включено).
- Группы по комнатам: дополнение держит в Z2M группу «Комната · <область>» для каждой области Home Assistant, где ≥2 лампы/реле, и обновляет её при изменении областей. Чужие группы не трогает. Нужен доступ к API Home Assistant (`homeassistant_api`).

## 2.14.2-bms.3
- Слой Tuya сам очищает старые группы на устройстве Tuya после первого знакомства с Z2M, если по базе Z2M устройство ещё ни в одной группе. Записи от хаба Tuya иначе мешают добавлению в группу Z2M (команда таймаутит). Группы, уже настроенные в Z2M, не трогаются; пульты и кнопки сцен тоже.

## 2.14.2-bms.2
- Координатор больше не нужно искать и вписывать руками: по умолчанию `serial.port: auto`. Дополнение само находит SLZB-06M в сетях Home Assistant (их спрашивает у Supervisor), запоминает его (`.bms-coordinator`) и при смене IP находит тот же координатор по серийному номеру (EUI64). Чужой координатор не берёт.
- Координатора ещё нет в сети — дополнение не падает, а ждёт: ищет каждые 30 с и пишет в журнал «Жду координатор SLZB-06M в локальной сети…» не чаще раза в 5 минут.
- Проверка прошивки: если у координатора EZSP старее v13 (EmberZNet ниже 7.4), Zigbee2MQTT не запускается, в журнале написано, что сделать (обновить прошивку по адресу `http://<ip>`); проверка раз в минуту, после обновления запуск идёт сам.
- Адрес, вписанный вручную (`tcp://…`, `mdns://…`, `/dev/…`), работает как раньше, без поиска. Для `tcp://` дополнительно проверяется прошивка. Адрес, который владелец вписал в `configuration.yaml`, при `auto` не затирается.
- Прежняя заглушка `tcp://IP_SLZB:6638` в настройках считается за `auto` (раньше запуск из-за неё останавливался).
- Режим `auto` требует нашего Zigbee-ядра; на штатном дополнение останавливается с просьбой вписать адрес вручную.

## 2.14.2-bms.1
- Новая установка настраивается сама, как шлюз Tuya: мощность передатчика 13 dBm и проверка «живо ли» (availability) включены по умолчанию.
- На самом первом запуске, до создания сети, дополнение измеряет эфир (утилита энергоскана из нашего ядра) и выбирает самый тихий канал.
  Не вышло — запасной канал 15 и предупреждение в журнале. Когда сеть создана, канал не меняется никогда.
- Существующий `configuration.yaml` не перезаписывается: умолчания пишутся только при отсутствии файла.
- Мастер быстрой настройки Z2M на новой установке не показывается (всё нужное дополнение знает из своих настроек).
- Образец `bms-models.example.yaml` кладётся в папку данных при каждом запуске; рабочий `bms-models.yaml` дополнение не создаёт и не трогает.
- `stage.sh` берёт слой Tuya из `tuya/layer/`; файлы без приставки `bms-` пропускает с предупреждением, а не падает.
