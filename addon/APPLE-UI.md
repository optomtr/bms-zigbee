# Прямой перенос desktop/iPhone макетов

Дополнение `2.14.2-bms.11`. Основные экраны берутся непосредственно из переданных `zigbee2mqtt-bms-desktop.html` и `zigbee2mqtt-bms-iphone.html`: та же разметка, исходные SVG, CSS, шрифтовый стек, размеры, тумблеры, сегментный индикатор и обработчики демонстрации.

Исходные файлы сохранены без изменений в `addon/design-reference/`. Тест сравнивает CSS, шрифтовые ссылки и встроенную логику с рабочими копиями. В образ попадают `desktop.html` / `iphone.html` и адаптер данных `reference-adapter.mjs`. Прежняя отдельная перевёрстка и её `style.css` удалены.

## Поведение

- `index.html` выбирает desktop или iPhone макет по ширине и сохраняет query/hash. В рабочем режиме используется прежний HTTP/WebSocket Z2M с тем же ingress-prefix и auth. Выбор макета не открывает отдельный сетевой порт.
- В `?demo=1` сохранены исходные три хаба, 14 устройств, переключатели, добавление хаба/устройства и демонстрационная карта. WebSocket не открывается; устройства вымышленные. Демо имитирует действия так же, как исходные файлы.
- Эффекты по умолчанию включены (`Полные`). Их длительности/кривые и режим `Спокойные` взяты из исходника. Сохраняются reduced motion и настройки темы/акцента.
- Шрифт сохранён буквально: системный стек Apple/SF и Inter fallback со ссылкой, которая уже была в исходных HTML. Новые шрифты и UI-библиотеки не добавляются. Встроенные React/ReactDOM из макета сохранены с MIT-лицензией в образе.
- Яркость и остальные writable exposes: удержание плитки примерно 0,45 с на телефоне, правый клик на компьютере; клавиатура — Alt+Enter на кнопке плитки или Enter на самой плитке. Дополнительная форма использует палитру и движение исходного sheet, собственный ползунок с круглым thumb. Команда отправляется по change, input изменяет только показание.
- Комнаты, группы, диагностика и расширенные настройки доступны внутри MQTT на компьютере и Брокера на телефоне. Они дополняют существующий экран и не перестраивают стартовую композицию.
- Команды, группы/endpoint, API transaction, ошибки, auth, offline, NCP и самопроверка используют существующие функции BMS. Управление offline блокируется, включая открытый ползунок. MQTT-state не подтверждает физическое исполнение; при переподключении команды не переигрываются.

## Настоящий API

Один экземпляр Z2M обслуживает один координатор. В live показываются его реальные устройства и параметры; демонстрационные seed/timers для команд, перезапуска, подключения и карты не используются. Управление экземпляром/добавление другого координатора остаётся в Home Assistant/расширенном интерфейсе. Переключатели, для которых backend не поддерживает операцию, не подменяют реальное изменение фиктивным успехом.

Live-карта запрашивается только вручную: `networkmap`, raw, без routes, ожидание до 120 секунд. Стиль карты исходный; связи берутся только из ответа. Демо-карта сохраняет исходную визуализацию и вымышленные связи.

## Проверка

- `node --test addon/test/*.test.cjs`: в том числе побайтное совпадение CSS, шрифтовых ссылок и исходной логики.
- `NODE_PATH=/path/to/dependencies node addon/test/frontend-browser.cjs`: Chromium. `BMS_UI_BROWSER=webkit` — тот же прогон в WebKit.
- Сравнение desktop 1440×1040 / iPhone 390×844 в светлой и тёмной теме с исходным HTML. Фиксируется только движение на время снимка; цветовой порог pixelmatch 0,01 отсекает округление одного уровня RGB в GPU-тенях. Стили сравниваются строго без допуска. Движение проверяется отдельно по исходным animation/transition и действиям.
- Команды, отсутствие ложного подтверждения, ползунок без input-потока, offline во время ввода, группы/endpoint/ошибки, auth, XSS, карта без автоопроса, demo без WebSocket.
- GitHub Actions повторяет оба браузера, ядро/Z2M/Tuya/harness, stage и Docker build. Настоящий HA ingress и физическое оборудование требуют приёмки установленного дополнения.
